## 22-11-26

**Phase:** Setup, then a reset of approach

### What I did

- Planned the engagement: I play client and architect, and the coding agent plays the dev team. Chose Go, local deployment, and a small but diverse feature set to widen the attack surface.
- Created the GitHub repo and pushed a documentation skeleton.
- Set `CODEOWNERS` to my GitHub handle.
- Set up SSH commit signing on Windows. Commits show **Verified** on GitHub once the key was registered as a *signing* key.
- Enabled Dependabot alerts and security updates, secret scanning, push protection, private vulnerability reporting, and Copilot Autofix. CodeQL is deferred until Go code exists.
- Created the `protect-main` ruleset:
  - Direct pushes and force pushes blocked
  - PRs required, with squash merge only
  - Linear history and signed commits required
  - `gitleaks` required as a status check
- Verified the ruleset. A force push to `main` was rejected with `GH013` ("Cannot force-push", "Changes must be made through a pull request"). A PR merged via the web UI worked.
- Simplified the repo structure, README, and `AGENTS.md` (details below).

### Decisions

- **Squash merge only.** GitHub signs the squash commit, so it passes the signed-commits rule.
- **Zero required approvals.** I'm the only contributor, so I can't approve my own PR. This is an accepted risk: there's no independent reviewer, and the PR flow plus the required check act as the compensating control.
- **No bypass actor** on the ruleset. If I ever need to override it, I disable it temporarily and log why.
- **Cut the process down.** The original 30+ document structure buried the actual learning goal. The new structure is five docs: `scope.md`, `threat-model.md`, `requirements.md`, `findings.md`, and `journal.md`. Traceability is kept inline: each requirement names the threat it answers, and each finding names the requirement it broke.
- **The agent doesn't touch git.** `AGENTS.md` now says so, and asks for a short completion summary (files, requirement IDs, tests, open doubts) instead of a PR description.
- Dropped for now: milestones, labels, ADR folders, runbooks, and phase tags.

### Slips and lessons

- Tested signing by committing to `main` instead of a branch, which left an empty test commit (`c405adc`) in history.
- Pushed a journal update straight to `main` before the ruleset existed, so no PR was created.
- Tried to delete three commits with a force push after the ruleset was active. It was rejected, which was the control working as designed, even against its owner. History on a protected branch is permanent, so correct it with a revert PR instead.

### Project Skeleton Implementation & Public Readiness (Dev Slice)

#### What was built
- **Go standard library skeleton:** Built `cmd/filterkappi/`, `internal/{config,httpserver,logging,storage}`, and `test/` targeting Go 1.22+ with zero third-party dependencies (`go.mod` has no external `require` directives).
- **Fail-closed configuration:** Loaded environment variables with strict validation for port ranges (1–65535), positive timeouts, positive body size limits, and valid log levels. Invalid configuration aborts startup with exit code 1. Provided safe `.env.example`.
- **Structured logging & request tracing:** Configured `log/slog` with JSON output handler. Added middleware to extract or cryptographically generate `X-Request-ID` and attach it to both context and logs without logging PII or secrets.
- **HTTP server hardening:** Configured `net/http.Server` with Go 1.22+ `ServeMux` method routing, `/healthz` endpoint (HTTP 200 JSON), explicit timeouts (`ReadHeaderTimeout`, `ReadTimeout`, `WriteTimeout`, `IdleTimeout`, `MaxHeaderBytes`), and signal-driven graceful drain (`SIGINT`/`SIGTERM`).
- **Abuse mitigations:** Implemented request body size limit middleware using `http.MaxBytesReader` returning HTTP 413, and panic recovery middleware returning generic 500 JSON to prevent internal information disclosure.
- **Containerization & isolation:**
  - Multi-stage `Dockerfile` with non-root user (`appuser:appgroup`, UID/GID `10001:10001`) on minimal Alpine 3.21 runtime.
  - `docker-compose.yml` with isolated internal bridge network; PostgreSQL database is **not exposed to the host interface**.
- **Developer tooling:** `Makefile` providing `build`, `test`, `lint`, and `vuln` targets.
- **Public repo readiness:** Audited working tree for secrets, local machine paths (`C:\Users\...`), and credentials. Parameterized passwords in `docker-compose.yml` (`${DB_PASSWORD:-...}`) and `.env.example` to ensure scanner compliance (Gitleaks, GitHub Push Protection).

#### Decisions
- **Zero external Go dependencies:** Pure standard library reduces supply chain risk to zero for the baseline skeleton.
- **Fail closed on bad configuration:** The application refuses to start if ports, timeouts, or body limits are misconfigured.
- **Network isolation over port convenience:** Refused to map port 5432 to the host in `docker-compose.yml`; the DB only talks to the app container.
- **Scanner-safe configuration:** Avoided hardcoded password literals in compose and env files to prevent false alarms from Gitleaks / GitHub Secret Scanning.

#### Verification
- Unit, abuse, and integration tests in `internal/config`, `internal/logging`, `internal/httpserver`, and `test/` all passing (`go test -v ./...`).
- Negative abuse tests verify out-of-range ports and negative timeouts fail startup, body size limit returns 413, and panics return generic 500.
